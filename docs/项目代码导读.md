# 项目代码导读（新成员必读）

本文档用于帮助新成员快速理解项目的技术栈、目录结构、核心函数、调用关系与日常开发入口。

## 1. 技术栈

- 运行环境：Node.js（用于脚本与本地开发服务）
- 前端：原生 HTML/CSS/JavaScript（无框架）
- Markdown 渲染：`marked`（CDN）+ `DOMPurify`（CDN）
- 内容存储：本地文件（`posts/*.md` + `posts/index.json`）
- 本地服务：Node `http` 模块（`scripts/dev-server.js`）
- 版本管理：Git

## 2. 核心目录结构

```txt
blog/
  assets/
    editor.js        # 编辑页逻辑（预览/AI摘要/发布/鉴权状态）
    main.js          # 首页列表加载
    markdown.js      # Markdown 渲染入口（marked + DOMPurify）
    post.js          # 文章详情页加载与渲染
    style.css        # 全站样式
  posts/
    *.md             # 文章 Markdown 源文件
    index.json       # 文章索引（由脚本生成）
    .ai-summary-cache.json   # AI 摘要缓存（git 忽略）
  scripts/
    dev-server.js    # 本地 HTTP 服务 + API + 编辑器鉴权
    generate-index.js# 扫描文章并生成索引/摘要
    check-content.js # 索引合法性检查
  editor.html        # 编辑页面
  index.html         # 首页
  post.html          # 文章页
  blog.config.json   # 本地配置（git 忽略）
  blog.config.example.json  # 配置示例（可提交）
  .env / .env.example
  package.json
```

## 3. 运行与构建链路

### 3.1 `npm run start`

调用顺序：
1. `npm run build`
2. `npm run generate:index`
3. `npm run check:content`
4. `npm run serve`（启动 `scripts/dev-server.js`）

### 3.2 各脚本职责

- `scripts/generate-index.js`
  - 扫描 `posts/*.md`
  - 解析 front matter
  - 生成 `title/date/description/excerpt/aiDescription/summarySource`
  - 写入 `posts/index.json`
  - 管理 AI 摘要缓存 `posts/.ai-summary-cache.json`

- `scripts/check-content.js`
  - 校验 `posts/index.json` 字段完整性
  - 校验日期格式、slug 唯一性
  - 校验对应 Markdown 文件存在

- `scripts/dev-server.js`
  - 提供静态文件服务
  - 提供编辑器 API（登录/摘要/发布）
  - 实现编辑器密码保护和会话

## 4. 页面与前端调用关系

## 4.1 首页 `index.html`

- 入口脚本：`assets/main.js`
- 核心函数：`loadPosts()`
  - `fetch("posts/index.json")`
  - 渲染卡片（标题、日期、AI 摘要、正文摘录）

## 4.2 文章页 `post.html`

- 入口脚本：`assets/post.js`
- 核心函数：`loadPostPage()`
  - 从 URL 读取 `slug`
  - 拉取 `posts/index.json` + `posts/{slug}.md`
  - 标题下展示 AI 摘要
  - 正文调用 `markdownToHtml()`

## 4.3 编辑页 `editor.html`

- 入口脚本：`assets/editor.js`
- 核心函数：
  - `refreshAuthState()`：查询登录状态，决定是否锁定按钮
  - `loginEditor()` / `logoutEditor()`：调用鉴权接口
  - `renderPreview()`：本地预览
  - `generateAiSummary()`：调用 `/api/summary`
  - `publishPost()`：调用 `/api/publish`，发布并重建索引

## 4.4 Markdown 渲染

- 文件：`assets/markdown.js`
- 核心函数：`markdownToHtml(markdown)`
  - 优先使用 `marked.parse()`
  - 用 `DOMPurify.sanitize()` 清洗 HTML
  - 若 CDN 失效，降级为纯文本 `<pre><code>`

## 5. 服务端 API 设计（`scripts/dev-server.js`）

## 5.1 鉴权相关

- `GET /api/editor/auth-status`
  - 返回是否启用密码保护、是否已登录
- `POST /api/editor/login`
  - 校验密码，签发 Cookie 会话
- `POST /api/editor/logout`
  - 清理会话

鉴权开关和密码来源：
- `blog.config.json -> editorAuth.enabled`
- 密码优先读 `process.env[editorAuth.passwordEnv]`
- 也可在配置里写 `editorAuth.password`（不推荐）

## 5.2 业务相关

- `POST /api/summary`
  - 登录后可调用
  - 读取 `blog.config.json` 的 AI 配置
  - 调 OpenAI-like `/chat/completions` 生成摘要

- `POST /api/publish`
  - 登录后可调用
  - 写入 `posts/{slug}.md`（包含 front matter）
  - 自动执行 `scripts/generate-index.js`

## 6. AI 摘要机制（两条链路）

## 6.1 批量链路（构建时）

- 位置：`scripts/generate-index.js`
- 触发：`npm run generate:index`
- 特点：
  - 支持 `mode: missing-meta / always`
  - 命中缓存时不重复调用 AI
  - `summarySource` 可追踪来源（`meta/ai/ai-cache/...`）

## 6.2 实时链路（编辑页按钮）

- 位置：`assets/editor.js` + `/api/summary`
- 触发：编辑器点击“AI 生成摘要”
- 特点：
  - 即时生成，适合写作过程
  - 失败时返回明确配置提示

  - `scripts/dev-server.js`

## 9. 典型调用链（必须理解）

### 9.1 发布文章

1. 编辑页点击“发布到网站”
2. `assets/editor.js -> publishPost()`
3. `POST /api/publish`
4. `scripts/dev-server.js -> publishPost(payload)`
5. 写 `posts/{slug}.md`
6. 执行 `scripts/generate-index.js`
7. 首页/文章页刷新后读取新索引

### 9.2 批量生成摘要

1. `npm run generate:index`
2. `scripts/generate-index.js`
3. 逐篇决定是否调用 AI
4. 写缓存 + 写 `posts/index.json`

## 10. 常见问题与排查

- 编辑器提示未登录：
  - 检查 `editorAuth.enabled`
  - 检查 `EDITOR_PASSWORD` 是否已设置
- AI 摘要失败：
  - 检查 `OPENAI_API_KEY`
  - 检查 `aiSummary.baseURL/model/apiKeyEnv`
  - 检查本地模型服务是否可访问
- 首页不显示新文章：
  - 确认 `posts/{slug}.md` 是否存在
  - 运行 `npm run generate:index`
  - 检查 `posts/index.json` 是否包含该文章
